## 2. Existing architecture

- Static Node.js 22+ build (`tools/build.mjs`), no runtime framework.
- GitHub Pages publishes `site/`.
- Generated SVGs, JSON data, Design Lab pages, architecture pages and
  illustration packages.
- Existing pages: home, community, map/hamlet, homes, cabin-a, lodge, living,
  participate, licensing, Design Lab gallery, residences, compare, editor,
  illustration, guides, visualisations, systems and archive pages.
- Existing Design Lab navigation is generated by `tools/lib/design-nav.mjs`.
- Existing browser/axe tests are Playwright-based; no new dependency is needed.

## 4. Existing pattern-like material

- `site/design-lab/patterns/` is a **container-configuration guide** (stacked,
  cantilever, courtyard, creek), not Alexander's pattern language.
- `site/design-lab/arrangements/` holds arrangement studies.
- The eight design principles in `README` and the ecological/accessibility docs
  overlap with the requested philosophy but are not structured for pattern
  navigation.
- The site plan, accessibility notes, climate/energy docs and illustration
  pipeline already contain evidence caveats that should be reused, not
  duplicated.

## 6. Gaps

- No verified pattern catalogue or source-verification metadata.
- No pattern-to-site-element identifiers.
- No pattern-to-design annotations in the editor.
- No scenario comparison or resident scenarios.
- No structured evaluation records.
- No pattern search/filter UI or shareable pattern pages.
- No explicit copyright/attribution policy for the pattern catalogue.

## 7. Proposed structure

Use existing conventions, not a parallel app:

```text
data/patterns/patterns.json      canonical pattern catalogue
data/patterns/schema.json        documented JSON Schema
site/design-lab/pattern-language/
  index.html                     generated public Explorer
  pattern-language.css
  patterns.js                    progressive search/filter
tools/lib/patterns.mjs           validation and verified title map
tools/lib/pattern-language-page.mjs
docs/design-philosophy.md
docs/pattern-language.md
docs/pattern-methodology.md
```

Future phases can add `data/scenarios/`, `data/evaluations/` and pattern
annotations in the existing Design Lab; they should not duplicate the six-home
baseline.

## 8. Source and copyright risks

- The 1977 book is copyrighted. Only pattern numbers/titles are referenced.
- Summaries and hamlet interpretations must be original.
- Numbers/titles must be checked against the primary source.
- Do not reproduce diagrams or long passages.
- Do not imply that Alexander endorses Containers Hamlet.
- Do not turn patterns into compliance rules or scores.

## 9. Baseline preservation

- The six selected homes remain the baseline.
- No existing page or URL is removed.
- New patterns are an overlay on the existing planning and Design Lab.
- Alternatives will be labelled conceptual.
- Static hosting, no credentials, no AI service.

## 10. Phased plan

1. **Phase 1:** verified 20-pattern catalogue, schema validation, philosophy,
   Explorer, detail panels, related links, search/filter, source/limits.
2. **Phase 2:** stable site-element annotations and site-plan highlighting.
3. **Phase 3:** three conceptual arrangements, baseline restoration, comparison.
4. **Phase 4:** lodge/cabin pattern annotations in the Design Lab.
5. **Phase 5:** resident scenarios and evaluation records.
6. **Phase 6:** accessibility/manual testing, visual regression, documentation.

Phase 1 is implemented in this branch. Later phases are specified but not
claimed as complete.
